# CSAE Reporting & Preservation Procedure — Halqa

**Status:** Manual stop-gap (v0.1 closed beta). Replaced by automated NCMEC pipeline in LAYLA-004 (v0.2).
**Owner:** Trust & Safety lead — Layla.
**Backend route:** `POST /api/admin/csae/preserve` ([source](../backend/src/app/api/admin/csae/preserve/route.ts)).

---

## 1. What this document covers

This is the **mandatory** workflow staff must follow when:

- A user files a report with `category: "CSAE"` via `/api/reports`.
- A moderator manually flags suspected CSAE content during stream review.
- Any external party (parent, law enforcement, NCMEC) notifies Halqa support of suspected CSAE.

**CSAE = Child Sexual Abuse and Exploitation.** Content depicting, soliciting, or facilitating sexual exploitation of any person under 18.

**Legal context:** US federal law (18 U.S.C. § 2258A) requires online platforms with US-resident users to report apparent CSAE to NCMEC's CyberTipline **as soon as reasonably possible** after obtaining actual knowledge. KSA Anti-Cyber Crime Law (Article 6) requires similar reporting to the National Cybersecurity Authority (NCA). Failure to report within a reasonable window is a criminal offense in both jurisdictions.

This procedure documents the **manual evidence-preservation flow** until LAYLA-004 ships an automated pipeline.

## 2. Triage SLA

| Step | Owner | SLA |
|---|---|---|
| Report arrives via `/api/reports?category=CSAE` | T&S queue | Immediate |
| Staff acknowledges (status → `triaged`) | First responder | **≤ 1 hour** |
| Evidence preservation (this doc) | First responder | **≤ 6 hours** |
| NCMEC CyberTipline submission | T&S lead | **≤ 24 hours** |
| Account action (ban + audit) | T&S lead | Immediate after preservation |

**Do NOT delay preservation to gather "more evidence."** A single preservation call snapshots everything in scope at that moment; you can re-run later if new evidence surfaces.

## 3. Step-by-step

### Step 1 — Acknowledge

1. Open the moderation dashboard, filter by `category: "CSAE"`, `status: "open"`.
2. Claim the report by POSTing to `/api/reports/{reportId}` with `{"status": "triaged"}`.
3. **Do NOT view or download any media yourself.** If the report references chat/profile content that auto-renders, screenshot is fine; if it references LiveKit recording or attached media that requires a click-through, **do not click**. Preserve via the endpoint instead.

### Step 2 — Preserve

Call:

```
POST /api/admin/csae/preserve
Content-Type: application/json
Authorization: Bearer <staff id token>

{
  "reportId": "<the reportId>",
  "note": "<one-line context>"
}
```

The endpoint will:

1. Resolve the report's `reportedUid`, `reporterUid`, `streamId`.
2. Snapshot user docs, the stream doc, chat messages (last 60 min), gifts (last 60 min), and the reported user's audit events (last 30 days).
3. Write all of that to `/csae_preserved/{caseId}` (immutable — no client write/delete allowed).
4. Write a `/audit_log` row with `action: "csae_preserved"`.

Response shape:
```json
{
  "caseId": "<auto-generated>",
  "created_at": "ISO timestamp",
  "subject": {
    "reportedUid": "...",
    "reporterUid": "...",
    "streamId": "...",
    "reportId": "..."
  },
  "counts": {
    "chatMessages": 142,
    "gifts": 7,
    "auditEvents": 5
  }
}
```

**Save the caseId.** You will reference it in the NCMEC submission and in the user-action audit row.

### Step 3 — Pull the preservation doc

The full payload lives at `/csae_preserved/{caseId}`. Read from the Firebase Console (staff-readable):
- Firebase Console → Firestore → `csae_preserved` → `<caseId>`.
- Export as JSON via the Console's `…` menu → "Export document".

### Step 4 — NCMEC CyberTipline submission (US-based or US-touching content)

1. Go to **https://report.cybertip.org/** (NCMEC CyberTipline).
2. Click "Make a CyberTipline Report".
3. Fill the form. Required fields:
   - **Type of incident:** select the closest match (most Halqa cases will be "Online Enticement of Children for Sexual Acts" or "Child Sexual Abuse Material (Apparent)").
   - **Suspect information:** copy from `payload.reportedUser` in the caseId doc. Use the `uid`, `email` (if present), `phoneNumber` (if present), `displayName`, `handle`, IP/UA if available in the stream doc.
   - **Victim information:** if known from `payload.reporterUser` (when the reporter IS the victim) or referenced in `payload.report.freeText`. **DO NOT include the victim's PII in the public summary fields** — NCMEC has separate restricted fields for that.
   - **Incident description:** free-form. Reference the `caseId` in the description: `Halqa case ID: <caseId>`. Paste the report's freeText.
   - **Content URLs:** if the content was a Halqa stream chat message or gift, there is no public URL — note "Hosted by Halqa, preserved internally as caseId <caseId>, available on subpoena."
   - **Attach evidence:** export the caseId doc as JSON (Step 3) and attach. If chat messages contain alleged CSAE text, that text is in the JSON.
4. Submit. Save the NCMEC report ID (`R-XXXXXXXX`) NCMEC issues on confirmation.
5. POST that report ID back to Halqa via `/api/admin/csae/preserve` again with a `note: "NCMEC report ID: R-XXXXXXXX"` — this creates a second `/csae_preserved/` doc that ties the NCMEC ID to the original caseId.

### Step 5 — KSA NCA notification (KSA-resident reporter OR reported user)

For KSA-resident parties (carrier prefix `+966` on the user doc), the National Cybersecurity Authority requires a parallel report:

1. Email: **report@nca.gov.sa** (verify current address at https://www.nca.gov.sa/ before sending).
2. Subject: `Halqa CSAE incident — caseId <caseId>`.
3. Body: include caseId, NCMEC report ID (if filed), and a one-paragraph summary in Arabic and English.
4. Attach the same JSON export.

### Step 6 — Account action

1. Permanent-ban the reported account via `POST /api/admin/users/{uid}/ban`:
   ```json
   {
     "reason": "CSAE — caseId <caseId>, NCMEC R-XXXXXXXX",
     "severity": "permanent"
   }
   ```
2. **Do NOT email the banned user.** Standard ban-notification flows are paused for CSAE cases to avoid tipping off the suspect before law enforcement can act.
3. If the reporter was a minor or appears distressed, flag the account to support for a wellness check (manual phone outreach in Arabic).

### Step 7 — Internal post-mortem

Within 7 days, the T&S lead writes a short post-mortem to `/csae_preserved/{caseId}.postmortem` (via Firebase Console; the field is admin-writeable on the doc but reject any other update). Include:
- Was the response within SLA? If not, why.
- Was the evidence sufficient for NCMEC? If not, what additional snapshotting capability do we need.
- Any LAYLA-004 requirements this case surfaced (e.g. LiveKit recording integration, multi-party preservation, etc.).

## 4. What the endpoint does NOT preserve

- **LiveKit recordings / Egress artifacts.** These live in cloud storage outside Firestore. If a recording exists, manually export it from the LiveKit dashboard (Settings → Recordings → search by streamId) and attach to the NCMEC submission. The egress filename pattern is `{streamId}/{date}.mp4`.
- **Avatar / image binaries.** Firebase Storage URLs are in the JSON, but the bytes are not. NCMEC can re-fetch via the Halqa subpoena process if needed.
- **Cross-account links.** If suspect operates multiple Halqa accounts, the endpoint only snapshots the one referenced. Investigators run cross-reference queries (`/users` where `phoneNumber == <X>`) separately.

## 6. Roadmap to automation (LAYLA-004)

The manual flow above is a stop-gap. The v0.2 pipeline will:

1. Auto-trigger preservation on `POST /api/reports?category=CSAE` (no staff click required).
2. Auto-submit to NCMEC via their API (we will need a CyberTipline reporting account + API key — apply early at https://report.cybertip.org/ipa).
3. Auto-export LiveKit Egress artifacts via the LiveKit Egress API and attach to the NCMEC submission.
4. Auto-permanent-ban the reported account on a confirmed CSAE category, with the human staff loop reduced to review-and-acknowledge.
5. SLA tracking + monthly compliance metrics.

Until that ships, **every CSAE report MUST go through the manual flow in this document.**
